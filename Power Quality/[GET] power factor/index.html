    /api/power-quality/power-factor

    PowerFactorRequestDTO

    Attributes:

    Name Type Description
    site_id int

    site id as int
    meter_id int

    meter id as int
    phase PhaseEnum

    element of PhaseEnum
    start_date datetime

    datetime
    end_date datetime

    datetime

    Like all start_date and end_date on the power quality set of endpoints, append 00:00:00 and 23:59:59 accordingly

    DataPointDTO

    Attributes:

    Name Type Description
    timestamp datetime

    datetime, auto adjusts based on start and end parameters
    value float

    float from the computation

    the value is calculated from the taiga wiki formula based on these columns:

        PHASE_COLUMNS = {
        "a": ("kwa", "va", "ia"),
        "b": ("kwb", "vb", "ib"),
        "c": ("kwc", "vc", "ic"),
    }

    Columns are chosen from the inputted phase

    and computed like this 

        apparent = voltage * current
    return (kw * 1000) / apparent if apparent else None

    May or may not change, note that pf_tot cannot be used as per the taiga wiki, so these are computed at runtime

    Due to this, the existence of these values is essential, the backend sends out a value of 0.0 if one of the column values is NULL

    NOTE: This is an active issue, sites are hit or miss on the stability of this endpoint

    PowerFactorResponseDTO

    Attributes:

    Name Type Description
    data List[DataPointDTO]

    list of datapoints, dynamic on length based on start and end parameters

    The increment calculation is derived from the same GraphClass already in standard could be 5 minute, 15 minute, 1 hour, or daily, depending on the parameters set
