    api/power-quality/harmonics/days

    HarmonicDaysRequestDTO

    Attributes:

    Name Type Description
    site_id int

    site id as int
    meter_id int

    meter id as int
    phase PhaseEnum

    element of PhaseEnum
    start_date datetime

    datetime (YYYY-MM-DD HH:MM:SS)
    end_date datetime

    datetime (YYYY-MM-DD HH:MM:SS)

    start and end date should have a time appended 00:00:00 and 23:59:59 respectively follows the enum conventions of phase

    PhaseEnum

    Attributes:

    Name Type Description
    ALL

    all
    A

    only a
    B

    only b
    C

    only c

    Follows the taiga wiki. This endpoint is very similar with the issues endpoint The same metric over/under limit is still done but the return shape is smaller

    Which means this endpoint /harmonics/day can be seen as a simpler return shape of /issues, which is then a by-day computation of /metrics all endpoints run by the same metrics analyzer class at the back-end

    AnomalyDayDTO

    Attributes:

    Name Type Description
    date date

    date (YYYY-MM-DD)
    types List[TypeEnum]

    a list of TypeEnums, could be only three: ['voltage'], ['current'], ['voltage', 'current']

    TypeEnum

    Attributes:

    Name Type Description
    VOLTAGE

    just for backend implementation
    CURRENT

    just for backend implementation

    HarmonicDaysResponseDTO

    Attributes:

    Name Type Description
    anomaly_days List[AnomalyDayDTO]

    list of AnomalyDayDTO

    Sample Request

      {
    "site_id": 64,
    "meter_id": 350,
    "phase": "all",
    "start_date": "2026-10-01 00:00:00",
    "end_date": "2026-10-12 23:59:59"
  }

    Sample Response

      {
    "anomaly_days":[
      {"date":"2026-10-06","types":["current"]},
      {"date":"2026-10-07","types":["current"]},
      {"date":"2026-10-08","types":["current"]},
      {"date":"2026-10-12","types":["current"]}
    ]
  }
